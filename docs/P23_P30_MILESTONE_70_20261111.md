## Architecture and risk

Alternative A: direct model-generated arbitrary filesystem/SQL actions with automatic approval and EXE packaging would improve apparent UX but increases costs, permissions, unbounded execution and private data risks. Alternative B (implemented): CPU-owned strict typed goal schemas, no customer file writes or automatic model authority, explicit local files, independent receipts and a source-only Python zipapp. Performance for local bounded input is deterministic, API cost zero, dependencies stdlib, maintenance burden much smaller.
